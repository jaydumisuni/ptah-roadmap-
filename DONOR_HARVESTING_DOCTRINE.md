# Ptah Donor Harvesting Doctrine

**Status:** ACCEPTED RECOVERY RULE — DOES NOT REOPEN PHASE 0A OR AUTHORIZE RUNTIME

This file extends the frozen donor-recovery method without restarting donor selection.

Ptah must not inspect a donor only for the subsystem or feature category that first caused the donor to be added.

## Whole-donor rule

For every existing or later donor:

```text
recover the whole relevant implementation
→ identify every mechanism it does well
→ compare each mechanism against current Ptah contracts/facilities and the wider TTG systems
→ route each useful improvement to the authority that actually owns that responsibility
→ decide adopt / adapt / wrap / reimplement / protocol-only / study-only / host-as-workload / reject
→ preserve licence and source boundaries
→ prove the resulting improvement
```

One donor may improve several Ptah Facilities or may reveal an improvement that belongs outside Ptah entirely.

The donor's advertised purpose does not limit what may be learned from it.

## Ptah boundary

Harvesting must not cause Ptah to absorb responsibilities it does not own.

Ptah remains the neutral mechanical Workspace/execution substrate. If a donor exposes a stronger mechanism for Hunter reasoning, Origins mission composition, CodeOps engineering, Sergeant review, Grid-Knight cybersecurity, Prime OS machine authority, or another external owner, that lesson is routed there rather than being forced into Ptah.

Likewise, a donor may strengthen multiple Ptah areas—for example lifecycle + recovery, environment + persistence, artifact + provenance, or browser + session recovery—when evidence supports those uses.

## Frozen Phase 0A rule

Phase 0A remains COMPLETE AND FROZEN.

Applying this doctrine to an already-inspected donor:

- does not reopen Phase 0A;
- does not automatically change frozen Ptah architecture;
- does not authorize code reuse;
- does not authorize runtime implementation;
- does not promote a donor merely because another useful mechanism is discovered.

Any newly discovered material that would alter accepted Ptah product/architecture must follow the existing change-control and roadmap-placement rules.

## Donor record consequence

When donor understanding changes, update the appropriate donor evidence with:

- newly identified mechanism;
- exact source/file/runtime evidence;
- current Ptah or external owner;
- comparison against existing capability;
- licence/code boundary;
- integration disposition;
- proof needed;
- whether the finding changes architecture, implementation detail only, or another TTG system.
